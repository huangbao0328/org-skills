# Site Progress 填报值历史治理

对「地盘进度」类导出做历史填报值（填报值）数据治理与可追溯交付。默认先对齐预注册，再跑治理，再按交付形态打包。

## 何时用

- 用户提供 Site Progress / 工序进度 xlsx（或 zip），要求修正历史倒退、同周冲突、可追溯备注，或「按参照包」做成按地盘周透视包。
- 触发词含：填报值治理、历史回写、同周以通过为准、改动清单、按地盘拆表、周透视。

## 输入约定

- 源数据：按**工序**的长表 xlsx（常见为 `工序名_全部地盘_时间戳.xlsx`），一行一次填报。
- 关键列（1-based，与现网导出一致时可直接用）：
  - 2 地盘编码 · 3 地盘名称 · 4 楼栋 · 5 标签 · 6 楼层 · 7 项目 · 8 reportDate · 9 **填报值** · 10 **状态**
- 状态：`1`=通过，`0`=审批中等非下线，`3`=已下线（治理时忽略）。

## 预注册（规划阶段必做，除非用户明示跳过）

对齐后再开跑：

| 项 | 默认草案 |
|---|---|
| 一句话问题 | 在不动行结构的前提下，把历史填报值修正为时间上不倒退，并给出可验收交付包 |
| 核心预测 | 改动集中在少数地盘×工序；同周多记录以通过为准后，表观「上调」多为审批中对齐通过 |
| A 符合 | 仅改填报值；行数不变；status=3 不动；同周非下线同步到代表值；交付含变更摘要与可核验数 |
| B 不符 | 增删行、改其他列、动 status=3、数字与摘要不一致、打不开 |
| C 排除 | 不重算业务进度、不上线改规则、不替业务裁定口径 |
| D 数据不足 | 列映射变了、状态码含义未确认、缺源 zip |
| 非目标 | 不做 UI/系统开发；不默认覆盖源文件 |
| 人判 / AI 干 | 人确认规则与验收；AI 写脚本、跑批、对账、打包 |

## 治理规则（v2，当前生效）

1. **忽略** status=3；空填报值跳过。
2. **只改** 填报值；不增删行；其他列原样。
3. **位置键**（工序文件内）：`(地盘编码, 楼栋, 标签, 楼层, 项目)`。
4. 按 reportDate **从新到旧**走：若更早周数值 **>** 更新周代表值，把更早周拉低到更新周（单调下拉）。
5. **同周多行**：代表值优先取 status=1（通过）中的数值（多条取 max）；若无通过则用该周非下线数值的 max；再把该周所有非下线行的填报值同步到代表值。
6. 因此个别审批中行可能被「上调」到通过值——这是同周对齐，不是进度通胀；摘要里要标出。

参考实现：工作目录下 `scripts/govern_fill_values_v2.py`（长表 in → 长表 out + `CHANGE_SUMMARY` + `change_stats.json`）。

## 交付形态（按需叠加）

### A. 长表治理包（默认中间态）

- 输出：与源同结构的 24（或 N）个工序 xlsx + 变更摘要（按文件/地盘/工序统计 value_writes）。
- 用途：对账、再导入、后续打包的数值源。

### B. 长表可追溯备注（可选）

- 对每个相对源有改动的填报值单元格：加 Excel Comment + 浅红底。
- 旧样式示例：作者 `数据治理`，填 `FFCCCC`，文案含原值→新值与状态。
- 参考：`scripts/annotate_fill_value_comments.py`。
- **注意**：若最终交付是周透视包，以形态 C 的备注样式为准，不必强依赖本步。

### C. 按地盘周透视包（参照样张，常用终态）

从**已治理长表**再打包，不重跑规则：

| 项 | 要求 |
|---|---|
| 目录 | `{地盘编码}-{地盘名称}/{工序名}.xlsx` |
| 工作表 | `说明`；有改动时才有 `改动清单`；其余每个填报周一张 |
| 周表 | 行=该周出现的楼栋/楼层；列=项目（機電类等用 `标签·项目`，标签空则仅项目名） |
| 格值 | 该周该键非下线记录的聚合（与参照一致：取 max）；空过程/无数据的地盘×工序不产出文件 |
| 改动 | `改动清单`列：周、楼栋、标签、楼层、项目、原值、新值、差值、状态；筛选+冻结 |
| 批注 | 作者 `历史数据修正`；文案多行：`本次修正：` / `原值 X → 新值 Y（状态N）`；同格多次改动叠在一条；底色 `FDE8E6` |
| 省略 | 源中 0 行过程（如空的地台瓦、機電T&C）；无改动则无 `改动清单` 表 |

参考：`scripts/package_by_site_v3.py`。有用户参照 zip 时，先解压对照再打包，用格值全量对账。

## 标准流水线

```
源 zip/目录
  → 预注册确认
  → govern_fill_values_v2（长表）
  → 自查：上调样本是否=同周通过同步；行数不变；status=3 未动
  →（可选）长表 annotate
  → package_by_site_v3（按地盘周透视）
  → 对账：改动条数 = 长表 value_writes；有参照则透视格 100% 对齐
  → 交付 zip + 一页摘要（规则、条数、已知cosmetic差异）
```

## 验收清单

- [ ] 行数与源一致（长表）；未改非填报值列
- [ ] status=3 单元格未改
- [ ] 变更摘要数字与脚本 stats / 改动清单条数一致
- [ ] 周透视包：说明表、改动清单、周表、批注作者与底色符合样张
- [ ] 与参照包对账时：透视值匹配率、批注文案匹配率达标；行序类差异标为 cosmetic

## 工作目录建议

```
<data-gov>/
  <source-exports>/
  scripts/          # govern_fill_values_v2.py, annotate_*.py, package_by_site_v3.py
  output-v2/        # 长表治理结果
  output-v3-by-site/
  CHANGE_SUMMARY_v2.md
  GAP_AND_FIX.md    # 有参照包时写差异与补齐说明
  *.zip             # 交付物
```

## 协作注意

- 规则变更（例如「审批中不同步到通过」）须新开预注册，禁止事后改门槛。
- 秘钥与业务未裁定口径不落盘臆造；列映射变了先停下来对齐。
- 结束后主动问是否记入组织「内部应用与 Skill 清单」。
