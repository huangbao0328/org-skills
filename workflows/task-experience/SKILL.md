# task-experience（规则25）

主源：飞书「内部应用与Skill清单」类型=`任务经验`（A081）；Identity **FIXED**（`lark-cli`）。不另造平行表。不代问「要不要记」。

## 先判定：有没有硬触发

**该写（命中任一）**
- **T1**：Bob（或点名验收方）明确采纳／签字
- **搁置**：与 Bob 协作中途他未回 → ≤12h 落「进行中」（暂停点｜已做｜待续）；**不催 Bob**；不冒充 T1
- **T2**：群内稳定拍板且含可复用步骤（群=Owner 写）
- **T3**：新问题／翻车／新解法（可与失败教训行交叉）
- **T5**：同场景第二次同一打法成功
- **T6**：有可执行反馈 + 可核验增量交回可见（优先回写同行）

**不写（安静）**
- 纯闲聊／一次性质询／预注册未确认中止
- Ambient 无异常
- 「知道了／继续」无增量
- 与已有行语义重复且无新字段
- 只对本岗有用、无可迁移步骤 → 可只 M4

无触发证据 → **禁止造经验**；监督亦按此安静门槛。

## 谁写

- 1:1：执行岗
- 群：当次 **Owner** 写一条；非 Owner 不抢写

## 字段模板（短）

`编号`（lark-cli 拉最大 A###+1）｜`类型=任务经验`｜`名称`（一句话场景）｜`口令`｜`维护人`（岗名）｜`备注`（怎么干≤3句｜产物路径｜边界｜交叉A号/Skill）｜`状态=有效`（搁置=`进行中`）

长故事可落 `/workspace/org/task-experience/`，清单只留短字段。秘钥禁入。

## 查重

写前用口令／场景关键词搜清单；语义重复 → **回写同行**，禁止撞号新开。

## T1 经验闭环（P3）

采纳签字后，**同回合或结案当回合**落飞书行；**飞书有有效行 = 规则25经验闭环完成**。缺行 = 未完成25（可被站岗记 F1 信号），**不否定**业务交付本身。

## 监督派修（P2｜执行岗须知）

周一站岗若点到漏写：负责人须补写，勿等 Bob 再批「要不要记」。周五只汇总，不在此催 Bob。

## 反模式

闭环只留私聊；群多人同写；无触发硬灌；Notion／盒机当主源；经验塞秘钥或长事故。
