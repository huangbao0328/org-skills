# 预注册对齐

## 何时用
任何**新任务进入规划**、准备动手执行（含让 AI/脚本/改配置）之前。机械闲聊、单纯查资料、用户已明确「先探索不验收」的可跳过，但须在回复里点明「本次不做预注册」。

## 硬规则
1. **先对齐，再执行。** 未获负责人确认 §1–§3 前，不写大批量脚本、不改生产配置、不宣布验收结论。
2. **标准写在结果前。** 预注册确认时间必须早于看数/上线验收；事后改标准无效，须开新单。
3. **人判 / AI 干。** 人写问题、预测、四态门槛并最终勾选；AI 只执行与出证据，不擅自改门槛。
4. **想改标准 = 新开一张预注册单**，旧单降级为探索性观察或作废。

## 规划阶段（Bot 必须主动做）
1. 用一两句话复述任务目标，并明确：本次要不要验收/证明什么。
2. 主动抛出预注册草稿（可短），至少含：
   - **一句话问题**
   - **核心预测**（能量化则量化）
   - **四态门槛**：A 符合预期 / B 与预测不符 / C 足以排除 / D 数据不足（互斥、可操作）
   - **非目标**（本次不证明什么）
   - **人判 vs AI/执行方分工**
3. 请负责人确认或改门槛；确认前只做只读摸底，不进入主执行。
4. 确认后记下确认时间，再开始执行。

## 一页字段（对齐时填齐）
| 块 | 必填 |
|----|------|
| 登记 | 事项名、负责人、执行方、确认时间、计划看结果时间、范围 |
| §1 问题 | 一句话 |
| §2 预测 | 核心预测、关键前提、非目标 |
| §3 四态 | A/B/C/D 各自标准 + 对应下一步 |
| §4 分工 | 人只做什么；AI/执行方只做什么 |

## 执行与验收
- 执行中发现 §3 歧义：先停，问人，不自行放宽或收紧。
- 看数后只勾选 A/B/C/D 之一，附证据；**不得回改 §3**。
- A：记通过；B：复盘后开新单；C：认错停做并沉淀失败案例；D：写明补什么数据、再等到何时。

## 可跳过（须明示）
- 纯问答、润色、格式转换
- 用户说「先随便看看 / 不验收 / 不做预注册」
- 已有仍有效的预注册单且范围未变（引用旧单编号即可）

## 团队口令
- 「先预注册，再动手」
- 「想改标准就开新单」
- 验收先问：规则写在结果前还是后？四态在哪？
