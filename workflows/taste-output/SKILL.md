# 视觉与输出品味（taste-output）

**文档定位**：品味约定，不是工程约定。判断「像不像我」而非「对不对」。  
**适用范围**：AI 协作产出的个人风格——视觉 / 文字 / 代码 / 文档组织。  
**与手册分工**：手册规则 **24.5** 只钩哲学五条短摘要 + 优先级链；**本 Skill 留全表**。  
**与其他文档**：认知锚点 / 规则 24.1–24.3 管「想得对不对」；`critical-questioning` 管「信不信」；ui-design-stack / 工程验收管「做得对不对」；本 Skill 管「像不像我」。  
**主框架**：哲学层（稳定）/ 偏好层（中期）/ 临时层（灵活）+ 挖锚点三法 + 七字段 + 冲突协议。  
**优先级**：品味红线 > 操作层 > 冲突协议 > 其余。  

---

## 0. 品味红线（4 条）

触发即 **停** → **报** → **问**（给 2–3 个风格选项，不问开放题）：

1. **风格人格分裂**：同一份交付内 ≥ 2 种互相打架的风格。
2. **装饰盖过信息**：动效/配色/装饰/华丽辞藻掩盖信息空洞。
3. **AI 油味**：对仗排比、过度修辞、空话套话、「首先/其次/最后」万能结构、廉价比喻。
4. **同类品味偏移不升级**：同一根因品味偏移 ≥ 3 次且未升级为正式偏好规则。

---

## 1. 操作层

### 1.1 启动三问（不确定就问，不猜）

1. **这份产出要「像谁」**？有没有参照物（产品/PPT/文章/网站/代码仓库）？
2. **风格落在哪个区间**（克制↔丰富 / 极简↔完整 / 工程感↔设计感 / 真实↔精致）？不确定标「待挖」，不猜。
3. **本次品味硬约束**（必须照搬 / 可自由发挥 / 必须避免）？

答案=本次临时品味锚点。

### 1.2 偏移信号 → 立刻停 → 1.3

| 信号 | 缺失锚点 | 典型表现 |
| --- | --- | --- |
| 风格滑移 | 哲学层 | 要极简却花哨；要工程感却设计感 |
| 装饰过度 | 哲学层 | 信息少、动效/配色/修辞堆满 |
| AI 油味 | 哲学层 | 排比、套话、廉价结构 |
| 风格分裂 | 偏好层 | 同交付多种风格打架 |
| 参照失准 | 临时层 | 给了参照，产出与参照不符 |

### 1.3 三步校准

1. **停产出**（不要补完再改）
2. **登记飞书清单**（规则 23 / 24.3 / 24.7 同轨；字段见 §6）
3. **修复**：能一句话修（「去掉这段排比」「换成工程化表达」）则直接改；不能则进 Plan

### 1.4 Plan 触发（同时满足任意两条）

- 偏移涉及 ≥ 2 类锚点（哲学/偏好/临时）
- 已完成 ≥ 30% 产出
- 大产出（页 ≥ 5，或单文件 ≥ 200 行，或多文件）
- 涉及哲学层冲突，需判场景优先级

## 2. 哲学五条（完整动作清单·精简版）

### 2.1 克制优于丰富

- 每个元素问「删了会怎样」，不影响信息就删。
- 配色 ≤ 3 类，字号 ≤ 4 级，字体 ≤ 2 种。
- 装饰（分隔线/底纹/图标/动效）默认不加，加了须有功能理由。

### 2.2 信息密度优先于装饰

- 一页/一段核心信息一眼可识别；装饰不能盖过信息。
- 视觉焦点 = 信息焦点。
- 层次靠字号/对比/留白，不靠底纹/边框/阴影。

### 2.3 结构可见优于风格统一

- 层级用缩进/编号/字号；分类用分组/分隔/标题；流程用箭头/编号；文档用目录/小标题/锚点。
- 骨架要看得见，风格是皮肤。

### 2.4 真实优于精致

- 不用对仗排比凑工整；不用「首先/其次/最后」万能结构；不用廉价比喻；不用「赋能/抓手/闭环/打通」空话。
- 数字就是数字，不「高达」「仅」「突破」。

### 2.5 工程感优于设计感

- 重复元素抽象成组件/模板；栅格/对齐/基线统一；命名/归档/版本可追溯。
- 代码：可读 > 巧妙，显式 > 隐式，标准库 > 第三方。
- 文档：目录结构清晰 > 写得漂亮。

---

## 3. 七字段规则格式

每条偏好规则必须七字段；**没有「参照」字段的规则不算数**。

```
规则名：<一句话命名>
喜欢：<具体描述，不是形容词>
不喜欢：<具体描述>
因为：<理由，使可推理到新场景>
参照：好样例 <作品/页面/段落> / 坏样例 <…>
适用边界：<什么时候不适用>
状态：已确认 / 待挖 / 临时
```

## 4. 偏好层 V / W / C / D（已确认 + 待挖占位）

### 4.1 视觉

**V-01 配色克制**｜状态：待挖  
喜欢：主色1+辅色1+警示1，低饱和，深浅靠明度。不喜欢：四色以上拼盘、渐变、高饱和撞色。因为：焦点散、色盲不友好。参照：待挖。边界：信息图/海报可放宽到4色；PPT/看板/界面不放宽。

**V-02 留白是元素**｜状态：待挖  
喜欢：留白 ≥ 内容面积 30%，关键周围加倍。不喜欢：填满、挤紧、「空就加东西」。因为：留白制造焦点。边界：高密度看板/报表可压到 20%，不低于 20%。

**V-03**：（待挖）

### 4.2 文字

**W-01 动词+名词，不要形容词+名词**｜状态：已确认  
喜欢：分析/拆解/校准/沉淀/升级 + 具体名词。不喜欢：赋能/抓手/闭环/打通/重塑；深层次的/多维度的/全方位的。因为：动词+名词落到动作。参照：好样例=本规则文档自身 / 坏样例待挖。边界：对外营销可放宽；内部文档/汇报不放宽。

**W-02 数字就是数字**｜状态：待挖  
喜欢：Q2 利润 120 万、下滑 12%。不喜欢：高达/仅/突破/显著/大幅。因为：修饰让数字变情绪。参照：待挖。边界：无。

**W-03**：（待挖）

### 4.3 代码

**C-01 可读优于巧妙**｜状态：待挖  
喜欢：显式循环 + 有意义变量名。不喜欢：一行式、隐式解构、过度函数式、看三遍才懂。因为：代码写给人看。边界：性能敏感可放宽。

**C-02**：（待挖）

### 4.4 文档组织

**D-01 目录结构优先于内容**｜状态：已确认  
喜欢：先定目录再写；目录有明确职责；命名自解释。不喜欢：先写后整理；「杂项/其他」；命名看里面才知。因为：结构对了内容归位。参照：组织原则文档树 / 坏样例待挖。边界：探索性草稿可放宽。

## 5. 挖锚点三法（按序）

人对「不喜欢」更敏感：反例 → 正例 → 历史。

1. **反例法**：产出后主动问「这次最不喜欢哪一处？为什么？」→ 反推喜欢 → 七字段写入偏好层。勿问「整体感觉怎么样」。
2. **正例法**：反例挖了 5–10 条仍不够 → 问「列出你觉得『像我』的 3 个作品，不用解释」→ AI 提炼共性 → 用户确认后写入，状态待挖。
3. **历史法**：积累若干次后 → 问满意/不满意各 2–3 个 → 满意挖共性（可标已确认）；不满意走反例法。

**攒锚点**：大量「待挖」是设计意图。同根因偏移 3 次必须升级为正式偏好（七字段）；优先补参照样例。登记表累计约 20 条复盘一次，直接改本 Skill，不另开文档。

## 6. 冲突协议

### 6.1 优先级链

```
工程红线（手册规则 24.1 / 既有 10–20）
  > 品味红线（本 Skill §0）
    > 工程操作层
      > 品味哲学层（§2）
        > 品味偏好层（§4）
          > 临时层（本次启动三问）
```

### 6.2 哲学层：信息密度 vs 克制（受众表）

| 场景 | 优先 |
| --- | --- |
| 给老板看（决策） | 克制 > 信息密度 |
| 给专家看（验证） | 信息密度 > 克制 |
| 给执行者看（操作） | 信息密度 > 克制 |
| 内部草稿/自查 | 信息密度 > 克制 |
| 对外正式交付 | 克制 > 信息密度 |

偏好层极简/留白 vs 完整性：同看受众；PPT/信息图偏极简，看板/报告偏完整；草稿偏完整、定稿偏极简；**同一页内不混用**。

无法用上表直接判的冲突 → 登记飞书（冲突案例），同场景累计 3 次升级为默认规则。

## 7. 登记走飞书（规则 23 / 24 同轨）

每发生一次品味偏移登记一条（短原则进清单；长故事可落 `/workspace/org/`）：

```
任务上下文：<一句话>
X（原意/品味）：<精确>
Y（理解/产出）：<精确>
偏移类型：哲学层 / 偏好层 / 临时层（具体到哪条）
根因：<一句，具体到哪条规则/样例>
修复：<一句或「进 Plan」>
是否升级：是/否（同类第几次）
```

同根因 3 次 → 七字段写入 §4 对应类。不升级不算修复。

---

## 8. 原则层（品味校准三原则）

1. **样例优于形容词**：参照字段空 → 停留「待挖」，不算正式规则。
2. **登记优于记忆**：写下来比记住重要；飞书清单是偏移史。
3. **升级优于重复**：修第三次问题在机制，改规则不改这次输出。

## 反模式

- 同交付风格人格分裂仍交付；装饰盖过信息；AI 油味当「完整」
- 无参照样例的形容词偏好当正式规则
- 品味压过工程红线；同页极简+完整混用
- 偏移不登记飞书、第 3 次仍不升级
- 未批前 UpdateSkill；把个人私密偏好写死进全员 Skill 正文
